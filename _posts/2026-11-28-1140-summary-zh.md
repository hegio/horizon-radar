<summary><strong>Linux 内核 nfsd 预认证漏洞 NFS2ROOT 披露，可远程获取 root 权限 ⭐️ 9.0/10</strong></summary>

网络安全公司 OpenSec 于 11 月 25 日披露 Linux 内核 NFS 服务器组件 nfsd 的预认证高危漏洞 CVE-2026-99362（命名为 NFS2ROOT，CVSS 9.8）。攻击者无需身份验证，只需向开放在 TCP 2049 端口的服务器发送构造的 NFS 请求，即可触发内核堆缓冲区溢出，经内存泄露和绕过 KASLR 后以 root 权限执行命令；OpenSec 展示了从触发到获取 root shell 的完整攻击过程。该漏洞代码自 2014 年（Linux 3.16）起已存在超过 12 年，影响启用 NFSv4.1 或 NFSv4.2 且 2049 端口可访问的文件服务器、NAS 设备和 Kubernetes 存储节点。修复已在内核 6.12.117、6.18.61、7.3.2 和 7.4-rc1 中发布，Debian 安全跟踪页面另列出 6.6.163、6.1.193、5.10.275 等修复版本；目前尚无该漏洞被实际利用的公开报告。

rss · IT之家 · 11月27日 22:36

**「背景」** nfsd 是 Linux 内核中实现网络文件系统（NFS）服务的组件，直接在内核态处理来自网络的 NFS 请求，因此其内存错误可能被远程转化为内核级代码执行。该漏洞由法国国家信息系统安全局（ANSSI）研究员 Jérémy Jean 于今年 8 月发现并提交修复方案，OpenSec 随后在 9 月底向 NFSD 维护人员提交了远程利用代码和补丁，此次披露即基于这一协调披露过程。

**「影响」** 运行 NFS 服务且 TCP 2049 端口对不可信网络开放的服务器、NAS 和 Kubernetes 存储节点面临远程无认证 root 接管风险，管理员应升级到已修复内核版本并在重启后使补丁实际生效；使用发行版定制内核的用户需依赖发行版以补丁回移方式提供的安全更新。暂时无法升级的设备，应通过防火墙将 2049 端口限制为仅允许可信客户端，或在无需文件共享时直接关闭 NFS 服务。

<summary><strong>购物网站出现利用 WebRTC 外泄数据的信用卡刷单脚本 ⭐️ 7.0/10</strong></summary>

安全研究人员在知名购物网站发现信用卡刷单（skimming）脚本，其特点是通过 WebRTC 通道而非传统 HTTP 请求外泄窃取的支付数据，以绕过针对常规网络流量的外泄监控。社区讨论中提到此类攻击目前仅针对移动设备，理由是移动端更难被检测。这属于已知 Magecart 类攻击手法的检测规避变体，并非范式级的技术突破。

hackernews · scanr · 11月27日 15:40 · [社区讨论](https://news.ycombinator.com/item?id=50668145)

**「背景知识」** Magecart 类攻击通过在网站支付页面注入恶意 JavaScript 来截获用户输入的卡号等信息，恶意脚本通常经由被入侵的第三方脚本进入页面。WebRTC 是浏览器内置的实时通信接口，其数据通道较少被常规流量监控工具覆盖，因此被攻击者用作替代性的数据外泄路径。

**「实际影响」** 对电商平台与企业安全团队而言，仅监控 HTTP/HTTPS 外泄请求已不足以发现此类窃取行为，需要将 WebRTC 数据通道纳入检测范围，并持续审计页面加载的第三方脚本。对普通用户而言，使用广告或脚本拦截器可降低暴露于恶意第三方脚本的风险，但只要网站继续嵌入第三方脚本，漏洞面就依然存在。

**「社区讨论」** 评论中最具实质性的观点来自 afavour：问题不在于 WebRTC 本身的技术能力，而在于该通道较少被监控，同样的手法同样可以用普通 HTTP 请求实现，且只要网站嵌入第三方脚本就始终存在风险。其他讨论围绕广告商是否应将广告沙箱化、禁止客户端执行第三方 JS，以及支付体系是否应采用非对称密码学替代对称密钥展开，观点分歧较大。
