hackernews · speedping · 11月18日 15:19 · [社区讨论](https://news.ycombinator.com/item?id=50547374)

**「背景」** Nginx 是互联网上广泛部署的 Web 服务器与反向代理，HTTP/2 支持需要在配置中显式启用（如 listen 指令加 http2 参数）。Wiz 是一家云安全研究公司，此次披露同时涉及一条完整的攻击链：除 Nginx RCE 外，还利用了一个 Linux SCTP 相关的本地提权漏洞以实现容器逃逸。

**「影响」** 所有启用 HTTP/2 的 Nginx 生产服务器均处于未认证 RCE 风险中，应立即应用供应商补丁或按披露方建议禁用 HTTP/2 作为临时缓解。由于 Nginx 部署基数巨大，即使按社区引用的 w3techs 数据仅约 12% 服务器启用 HTTP/2，潜在受影响规模仍然可观；容器化环境中攻击者还可借助配套提权漏洞进一步逃逸。

**「社区讨论」** 评论者 black3r 批评披露时序：修复补丁已在开源仓库提前一周提交，且提交信息含 "Reported by Xint.io" 字样，任何监控此类仓库的人均可在此期间发现并利用该漏洞，他认为 F5/Nginx 或报告团队本应提前发布安全公告。评论者 fduran 指出 HTTP/2 并非 Nginx 默认启用、仅约 12% 服务器受影响以缩小恐慌。评论者 aftbit 则提醒，利用链中用于容器逃逸提权的 Linux SCTP 漏洞疑似尚无公开 CVE 编号的零日漏洞，可能仍在与内核团队协调修复。

<summary><strong>NGINX2Root 攻击链披露：未认证 RCE 结合内核漏洞可逃逸容器 ⭐️ 9.0/10</strong></summary>

11 月 18 日，安全研究团队 Xint Security Research 公开披露名为 NGINX2Root 的漏洞链：5 个无需身份认证即可远程执行代码的 Nginx RCE 漏洞（CVE-2026-123007、CVE-2026-123634、CVE-2026-123633、CVE-2026-121810、CVE-2026-113425），分别涉及 HTTP/2、HTTP/3、反向代理及邮件代理模块，无需同时利用；叠加 Linux 内核 SCTP 子系统提权漏洞后，攻击者可从 Docker 容器内 Nginx Worker 权限提权并突破容器隔离，最终取得宿主机 root 权限。其中影响较广的 CVE-2026-123007 源于 HTTP/2 流量控制整数溢出导致的堆内存越界写入，凡监听端口启用 HTTP/2 的 Nginx 均可能受影响。CERT-EU 同日公告称 F5 已公开处理这 5 个漏洞、截至公告时未见野外利用报告；Sophos 确认 Nginx 开源版 1.30.7 与 1.31.9 已包含修复，Nginx Plus 也已发布对应修复版本。目前该信息为单一媒体对研究团队报告的转述，具体影响面与修复状态尚待官方公告进一步确认。

rss · IT之家 · 11月18日 23:20

**「背景」** Nginx 是全球部署最广泛的 Web 服务器与反向代理之一，其 HTTP/2、HTTP/3、邮件代理等功能随不同配置启用，攻击面因此取决于各实例的具体配置。Docker 等容器环境依赖 Linux 内核机制实现隔离，所谓“容器逃逸”通常需要容器内应用漏洞（此处为 Nginx RCE）与内核提权漏洞（此处为 SCTP 子系统漏洞）组合，才能从容器内进程触及底层宿主机。

**「影响」** 运行面向互联网开放的 Nginx 服务的管理员应优先排查并升级至 1.31.9（或 1.30.7），Nginx Plus 用户升级至对应修复版本；暂时无法升级时可关闭 HTTP/2 以缓解 CVE-2026-123007 与 CVE-2026-123633，但该措施对其余三个漏洞无效。由于研究团队称完整攻击链已在 AWS、谷歌云和微软 Azure 等云环境完成演示验证，容器化部署 Nginx 的团队除升级 Nginx 外还需关注 Linux 内核 SCTP 漏洞的修复进度。
