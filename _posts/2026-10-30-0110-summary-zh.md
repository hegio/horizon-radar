2026 年 10 月 29 日，安全研究员 Orange Tsai 发表研究，展示仅利用逻辑漏洞（不依赖内存损坏或堆操作）即可构建攻破 Microsoft Edge 的完整攻击链。文章声称，通过一个携带凭据的简单 fetch 请求，任意网站即可获取 Edge 用户的邮箱地址，并以此为基础串联起整个链条；作者还附带了从计算器反向调用 Edge 的演示视频。这是已公开披露的研究成果，而非计划中的方案。

hackernews · austinallegro · 10月29日 06:47 · [社区讨论](https://news.ycombinator.com/item?id=50285319)

**「背景」** Microsoft Edge 基于 Chromium 内核，但微软在其上添加了大量与 Windows 系统及自家服务（如账户与邮件体系）深度集成的自有功能。这类“浏览器—系统”交叉集成扩大了逻辑类攻击面：即使内存安全无懈可击，权限校验、URL 解析或功能开关等设计层面的缺陷仍可能被逐个串联成完整攻击链。Orange Tsai 是长期从事浏览器与 Web 攻击面研究的知名安全研究员，此前多次公开高质量的漏洞链分析。

**「影响」** 该研究为浏览器厂商提供了可复现的警示：在 Chromium 之上叠加系统集成功能时，每一处跨组件信任边界都可能成为纯逻辑漏洞的入口。对 Edge 用户而言，在相关逻辑缺陷被修复前，访问恶意网站理论上即可泄露与 Microsoft 账户关联的邮箱等信息；浏览器安全团队应重新审视内置功能与 Web 内容之间的数据流与权限设计。

**「社区讨论」** 评论者 darkamaul 称赞该链条“没有内存损坏、没有堆操作，纯逻辑漏洞”且讲解清晰，并指出作者还发布了从计算器反向弹出 Edge 的演示视频；its-summertime 与 akersten 借此表达对浏览器与网站、系统交叉集成的担忧，后者直言微软在他人浏览器内核上添加自有功能只会让 Edge 更不安全；adzm 则对“带凭据的 fetch 即可获取任意用户邮箱”这一细节表示不安。以上均为评论者的个人观点，文章中的技术细节尚未见独立验证。

<summary><strong>微软发布 DXR 自 2018 年以来最大更新 ⭐️ 8.0/10</strong></summary>

微软于 10 月 28 日发布 DirectX 12 Agility SDK 1.620 正式版与 1.722 预览版，为 DirectX 光线追踪（DXR）引入集群几何体、分区顶层加速结构（PTLAS）和 GPU 驱动的间接加速结构构建，以降低复杂动态场景的光追开销。集群几何体将几何数据划分为最多含 256 个三角形和 256 个顶点的可复用集群；在微软公布的 D3D12RaytracingClusteredGeometry 示例中，AMD Radeon RX 9070 配置下帧率从传统 BLAS 方案的 1.2 FPS 升至 79 FPS（约 66 倍），加速结构构建时间从 788 毫秒缩短至 3.11 毫秒，总内存占用从约 7.3 GiB 降至 774 MiB。微软强调上述数据来自特定开发示例与测试配置，不代表所有游戏都能获得相同提升，实际效果取决于工作负载、引擎实现方式和 GPU 架构。首批支持范围包括所有英伟达 GeForce RTX 显卡、AMD Radeon RX 9000 系列以及英特尔 Arc B 系列独立显卡和部分酷睿 Ultra 核显，新功能不要求全新硬件特性但仍需厂商驱动支持。

rss · IT之家 · 10月29日 14:27

**「背景」** 光追需要构建和更新包围体层次结构（BVH）等加速结构，以便 GPU 快速判断光线与几何体的相交关系；在包含大量动画、几何体流式加载和频繁变化物体的场景中，反复重建这些结构会带来较高计算开销。英伟达此前在《战争机器：事变日》中采用的 RTX Mega Geometry 技术是缓解该问题的私有方案，此次更新将类似思路标准化到 DirectX 接口中，使不同显卡厂商的开发者可通过统一接口使用集群几何体等技术。

**「影响」** 开发者有望在光栅化渲染和光线追踪中复用同一套高精度几何数据，减少为光追单独制作简化模型的需求，并改善反射和阴影与实际场景的匹配程度；但各功能的实际可用性取决于显卡厂商的驱动实现与验证进度，例如 1.620 正式版中的部分图形程序（Partial Graphics Programs）目前仅支持 AMD Radeon RX 7000 和 RX 9000 系列显卡，开发者接入前需确认目标硬件的驱动支持情况。
