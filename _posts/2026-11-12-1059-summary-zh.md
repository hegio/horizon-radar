**「背景」** GitHub Actions 中第三方 action 通常以 tag 或分支名引用，而 tag 可被仓库所有者移动或替换，使 CI 实际拉取的代码与预期不一致，这是 CI 供应链攻击的常见途径。固定到 commit hash 可让每次运行解析到同一份代码，评论区也确认这是当前讨论的前提：问题在于你信任谁——是承诺不移 tag 的仓库所有者，还是把某 commit hash 合并进锁文件的人。

**「影响」** 准备采用 workflow lockfile 的团队需要核实其覆盖范围。据 zizmor 维护者 woodruffw 补充，当前 lockfile 只锁定普通 action 调用：若工作流调用了其他可复用工作流（reusable workflows），这些引用暂时仍需手动做 hash-pin；composite actions 本身不被直接锁定，只通过调用它的工作流间接锁定，因此单个调用方仍可能受未锁定内容影响。

**「社区讨论」** 讨论焦点是信任模型：Already\_\_Taken 认为，固定 commit hash 是把“信任 repo 所有者不移 tag”换成“信任合并该 hash 的人已核实它来自目标仓库而非某个 fork”，并主张 GitHub 应强制 marketplace 上的 tag 不可变。klodolph 的态度更激进，建议除非不可避免否则尽量少用 GH actions；SchemaLoad 则建议直接把 action 代码复制进自己的配置以完全锁定，而非引用来源不明的脚本。这些均为个人观点，不代表已确立的结论。
