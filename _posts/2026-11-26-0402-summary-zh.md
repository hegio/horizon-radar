hackernews · rgwohlbold · 11月25日 13:33 · [社区讨论](https://news.ycombinator.com/item?id=50642086)

**「背景」** 整数分解与离散对数是 RSA、椭圆曲线密码（ECC）等公钥体系长期依赖的困难问题：一旦出现高效解法，相应的加密与数字签名机制将失去安全性基础。近年来业界持续投入 AI 数学推理与定理证明，社区讨论也常把此类成果与 AlphaGo 通过搜索突破复杂博弈空间相类比。

**「影响」** 对部署 RSA/ECC 系统的机构与密码学研究者而言，需要阅读并评估这些论文是否对现有安全假设构成新的算法威胁；但在来源未披露具体结果之前，尚不构成迁移或更换加密体系的依据，实际影响取决于论文经同行评议后的结论。

**「社区讨论」** fidotron 转述其称为可信人士的说法，称这只是更大进展的冰山一角（属传闻，未经证实）；martythemaniak 认为 AI 数学发现并不意外，将其类比为 AlphaGo 对巨大搜索空间的探索。unknown-unknown 表示，评论者所称的 Navier-Stokes、黎曼猜想、Erdős 问题等近期进展（均为其个人列举）动摇了“数学问题无法靠投入资源攻克”的既有判断。

<summary><strong>1Password 安全事件：攻击者经被攻陷员工设备向生产服务推送恶意代码 ⭐️ 8.0/10</strong></summary>

2026 年 11 月 25 日，1Password 通过官方博客披露了当月安全事件的细节：攻击者利用一台被攻陷的员工设备，向后端生产服务推送了恶意代码。公司同时公布了整改措施，但社区评论指出公告未说明事发时是否缺少分支保护规则（如禁止直接推送至主分支），或这些规则是否被攻击者绕过。

hackernews · lxhrstn · 11月25日 17:18 · [社区讨论](https://news.ycombinator.com/item?id=50644817)

**「背景」** SaaS 供应链攻击的典型路径是：攻击者先攻陷员工终端，再利用终端上的开发者凭据向代码仓库推送恶意代码；若恶意代码经部署管道进入生产环境，则整个服务被攻陷。随着公司员工数量增长，某一台员工设备被攻陷的概率趋近于必然，这使该向量长期被视为 SaaS 公司面临的最主要安全威胁之一。

**「影响」** 对 1Password 用户而言，此次事件引发了对密码管理器集中式信任的担忧——社区成员指出，若恶意代码进入生产环境，存在在客户端解密后窃取明文密钥的潜在风险。对 SaaS 企业而言，事件凸显了分支保护和部署管道安全作为关键防线的必要性。

**「社区讨论」** tptacek 指出“被攻陷的员工设备→向代码仓库推送恶意代码→部署到生产环境”是 SaaS 公司最重要且最常见的攻击向量；ctidd 认为公告未说明是否禁止直接推送至主分支是“一个巨大的危险信号”；部分长期用户因此事件更加倾向于使用本地存储的密码库，K0nserv 则担心将 Passkey 存入 1Password 会弱于“密码+外部第二因素”的安全姿态。

<summary><strong>SK 海力士计划 4 至 5 年内量产 100 层堆叠 3D DRAM ⭐️ 8.0/10</strong></summary>

SK 海力士资深工程师崔康植在首尔大学 AI 半导体论坛披露，公司目标在 4 至 5 年内实现 3D DRAM 量产，首款商用产品将采用 100 层垂直堆叠存储单元；约 75 层即可达到现有 10nm 级 DRAM 的同等密度。公司已完成存储单元样片制造并验证了器件工作特性，刷新性能可以对标传统 DRAM；100 层方案可用现有设备制造，但 200 层及以上需要专用新设备，长期计划借鉴 3D NAND 的多层堆叠与混合键合技术冲击 1000 层以上。这是路线图披露而非已落地产品，距离量产仍有 4 至 5 年。

rss · IT之家 · 11月25日 13:33

**「背景」** 传统平面 DRAM 依靠电容储电，单元尺寸越小储电量越低、漏电流和电阻越高，微缩已逼近物理瓶颈；3D DRAM 不再缩小平面尺寸，改用垂直堆叠提升密度，通过多层硅与硅锗薄膜堆叠、刻蚀制造，与 HBM 的多颗 DRAM 裸片堆叠、DRAM 叠在逻辑芯片上的方案不是一回事。为控制成本与互联复杂度，SK 海力士提出只按需激活目标电路的选择器架构以缩减互联占用面积、降低电路负载，并借鉴 3D NAND 的刻蚀整合工艺；团队还在研究用铟镓锌氧化物（IGZO）替代硅做晶体管沟道，其漏电流更低、数据保存时间更长，但氢等因素会改变材料特性，可靠性问题尚未解决。

**「影响」** 首款 100 层产品仅比达到现有 10nm 级密度所需的 75 层多约三分之一，初期相对现有产品的密度优势有限；要真正拉开差距需推进到 200 层以上，而这依赖专用新设备以及 IGZO 沟道等材料可靠性问题的解决，意味着量产时间表和最终层数目标仍存在不确定性。

<summary><strong>Minecraft Java 版曝 FreeType 高危 RCE，1.20.5 起全版本受影响 ⭐️ 8.0/10</strong></summary>

11 月 22 日公开的 minecraft2shell 披露，Minecraft Java 版存在高危远程代码执行漏洞：攻击者可通过服务器资源包中的特制 TrueType 字体触发 FreeType 2.14.3 及更早版本的原生越界写入，已在 Java 版 26.3 Windows 客户端上验证任意代码执行。受影响范围包括 1.20.5 至 1.21.10 正式版以及 26.1 至 26.4 快照；1.20.4 及更早版本和基岩版不受影响。Mojang 目前仍使用 lwjgl-freetype 3.4.3，尚无官方补丁；社区于 11 月 24 日发布 m2sfix 1.0.0，以 Java agent 或 mod 形式关闭字体 hinting 作为临时修复。

telegram · zaihuapd · 11月25日 12:46

**「背景」** FreeType 是被广泛使用的开源字体光栅化库，Minecraft Java 版通过 LWJGL 绑定的 lwjgl-freetype 3.4.3 调用它来渲染 TrueType 字体；由于该绑定捆绑的 FreeType 版本不高于 2.14.3，游戏客户端在解析资源包内字体时继承了底层库的内存安全缺陷。漏洞根因位于原生层而非 Java 层，因此常规的 Java 安全沙箱限制无法阻止其触发。

**「影响与建议」** 在官方补丁发布前，玩家若加入不可信服务器或安装来路不明的资源包，客户端可能被直接执行任意代码。投稿人建议采取三项应急措施：暂不添加任何资源包、将多人游戏的服务器资源包权限设为“禁用”、或安装社区临时修复 m2sfix；由于 PoC 已经公开，服务器管理员也应避免向玩家推送未经审核的资源包。
